# Lifecycle

| stage | job | ends with |
|---|---|---|
| L1 Plan | keep the ask intact | a story, or a direct ticket |
| L2 Size | type, then size | a size a person confirmed (G0, triage confirm) |
| L3 Build | build and prove | the route's gates passed |
| L4 Release | see it working | a person has seen it in the running product · the release's release notes, updated from each PR's release-notes line |
| L5 Learn | write it down | the closing notes · the decisions log · the library |

Plan starts on Intake, which has two tabs. Queue is where requests arrive, in four stage columns. Ideas holds the Ideas list. Each idea on it is one file in the team repo's `ideas/`, numbered I-001, I-002 and so on. A person takes an idea from the list to Brainstorm, to Define (the story is written first) or to Direct (straight to type and size).

The full loop, with the human review map, is on the method's Lifecycle page, `docs/manual/lifecycle.html` in the Ways of Working repo.
